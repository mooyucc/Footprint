# 发现地图功能快速测试指南

## 🚀 快速开始

### 前置条件检查

在开始测试前，请确认：

1. ✅ **CloudKit Schema 已创建**
   - 访问 [CloudKit Dashboard](https://icloud.developer.apple.com/dashboard/)
   - 确认 `PublicDestination` Record Type 已创建
   - 确认所有字段已添加（见 `CloudKit配置指南.md`）

2. ✅ **真机测试**
   - CloudKit 功能需要在真机上测试（模拟器可能无法正常工作）
   - 确保设备已登录 Apple ID

3. ✅ **网络连接**
   - 确保设备有网络连接（CloudKit 需要网络）

---

## 📝 测试步骤

### 测试 1：共享目的地

1. **打开 App**，进入地图页面
2. **编辑一个目的地**（或创建一个新的）
3. **打开「共享到发现地图」开关**
4. **保存**
5. **检查控制台日志**，应该看到：
   ```
   ✅ 已共享目的地到公共数据库: [地点名称]
   ```

**预期结果：**
- 保存成功
- 控制台显示成功消息
- 无错误提示

**如果失败：**
- 检查 CloudKit Schema 是否正确创建
- 检查设备是否登录 Apple ID
- 检查网络连接
- 查看控制台的详细错误信息

---

### 测试 2：查看发现地图

1. **切换到「发现地图」模式**（点击顶部的「发现地图」按钮）
2. **等待几秒**（给 CloudKit 查询时间）
3. **检查地图上是否显示了你共享的地点**

**预期结果：**
- 地图上显示你共享的地点
- 地点标注正常显示
- 控制台可能显示：
  ```
  🔍 开始查询公共目的地，区域: ...
  ✅ 加载了 X 个新的公共目的地，总计: X
  ```

**如果看不到地点：**
- 等待更长时间（CloudKit 查询可能需要几秒）
- 检查控制台是否有错误
- 确认 CloudKit Schema 中的 `location` 字段类型是 `Location`
- 尝试移动地图，触发重新加载

---

### 测试 3：取消共享

1. **编辑已共享的目的地**
2. **关闭「共享到发现地图」开关**
3. **保存**
4. **切换到「发现地图」模式**
5. **检查该地点是否消失**

**预期结果：**
- 保存成功
- 控制台显示：
  ```
  ✅ 已取消共享目的地: [地点名称]
  ```
- 在发现地图中，该地点不再显示

---

### 测试 4：多设备/多账号测试

#### 多设备测试（同一 Apple ID）

1. **在设备 A 上共享一个地点**
2. **在设备 B 上**（同一 Apple ID）切换到「发现地图」
3. **检查是否能看到设备 A 共享的地点**

**预期结果：**
- 设备 B 能看到设备 A 共享的地点
- 可能需要等待几秒（CloudKit 同步延迟）

#### 多账号测试（不同 Apple ID）

1. **使用账号 A 登录设备 A**，共享一个地点
2. **使用账号 B 登录设备 B**，切换到「发现地图」
3. **检查是否能看到账号 A 共享的地点**

**预期结果：**
- 设备 B 能看到账号 A 共享的地点（因为公共数据库对所有用户可见）

---

### 测试 5：地图移动和缩放

1. **在「发现地图」模式下**
2. **移动地图到不同区域**
3. **缩放地图**
4. **检查是否自动加载新区域的公共点**

**预期结果：**
- 地图移动时自动加载新区域的公共点
- 控制台显示加载日志
- 不会重复加载同一区域（有缓存机制）

## 🔍 调试技巧

### 查看 CloudKit 数据

1. 访问 [CloudKit Dashboard](https://icloud.developer.apple.com/dashboard/)
2. 选择 Container **`iCloud.Mooyu.Footprint`**，环境 **Development**
3. 进入 **Data** > **Public Database**
4. 查看 `PublicDestination` 记录
5. 确认记录已创建，字段值正确。若看不到 Record Type，多半是 Schema 未 **Deploy Schema Changes** > Development

### 查看控制台日志

在 Xcode 中查看控制台输出，关键日志包括：

- `✅ 已共享目的地到公共数据库` - 共享成功
- `✅ 已取消共享目的地` - 取消共享成功
- `🔍 开始查询公共目的地` - 开始加载
- `✅ 加载了 X 个新的公共目的地` - 加载成功
- `❌ 加载公共目的地失败` - 加载失败（查看错误详情）

### 常见错误排查

#### 错误 1：`Did not find record type: PublicDestination` / `recordType 'PublicDestination' does not exist`

**原因：** Schema 未创建，或**已创建但未部署**（最常见）

**现象：** 发现地图仍可能显示你**自己**已共享的地点（来自本地 SwiftData），但控制台报错，且拉不到**其他用户**的公共点。

**解决：**
1. 若未创建：按 `CloudKit配置指南.md` 创建 `PublicDestination`、字段、索引、权限
2. **若已创建仍报错：** 在 CloudKit Dashboard 点击 **Deploy Schema Changes**，选择 **Development**，部署到开发环境。未部署则 App 查询会一直报此错

#### 错误 2：`Field 'recordName' is not marked queryable`（仅 Dashboard）

**出现位置：** CloudKit Dashboard > **Data > Records**，选择 `PublicDestination` 查询时。

**原因：** `recordName`（系统字段）未添加 Queryable 索引，Dashboard 的 Records 查询界面无法列出记录。

**解决：** 在 **Schema > Indexes** 中为 `PublicDestination` 添加 **`recordName`** 的 QUERYABLE 索引（见 `CloudKit配置指南.md` 第四步）。  
**说明：** 此错误只影响在 Dashboard 里浏览 Records，**不影响 App 端**的发现地图查询。

#### 错误 3：`field 'location' is not queryable`

**原因：** `location` 字段未创建 Queryable 索引

**解决：** 在 CloudKit Dashboard 中为 `location` 字段创建 Queryable 索引

#### 错误 4：`not authenticated`

**原因：** 设备未登录 Apple ID 或 CloudKit 权限问题

**解决：** 
- 检查设备是否登录 Apple ID
- 检查 App 的 CloudKit 权限设置

#### 错误 5：查询返回空结果

**原因：** 
- 没有共享的地点
- 查询区域不匹配
- Schema 字段类型不匹配

**解决：**
- 确认有地点已共享
- 检查 CloudKit Dashboard 中是否有记录
- 检查字段类型是否正确
